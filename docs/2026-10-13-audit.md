# 2026-10-13 audit of the use-omp skill

This audit asked how agents actually used the skill in its first week, whether its claims still held for the installed omp, and what would make delegation more reliable and observable. It led to the wrapper, the records, and decisions 1 to 11 in [decisions.md](decisions.md). A second usage audit, on 2026-10-21, is [at the end](#usage-audit-2026-10-21).

## Method

- **Usage history:** Claude Code transcripts and session indexes from 2026-10-06 to 2026-10-13, plus omp's own session store.
- **omp 18.10.3:** installed help, the installed package's changelog, and its TypeScript source. Each claim the skill makes was traced to a file and line.
- **omp itself:** consulted headlessly (`openai-codex/gpt-6.1-sol`, medium and high effort) to review the skill and later the diff. These runs doubled as live tests of the recipe.
- **Controlled experiments:** live runs at low effort that probed the claims the skill depends on (below).
- **Reviews:** six rounds of source-checked adversarial review (Opus), two omp reviews, and three cold-start usability tests. In each cold-start test, a fresh agent followed only the skill to do a real delegation and logged every point of friction.

Scouting and extraction were delegated to cheaper models. Key claims were re-checked against source before they were relied on.

## What usage looked like (2026-10-06 to 2026-10-13)

- **Loads:** the skill loaded in over a dozen sessions, mostly through the slash command, with some model-initiated and subagent loads.
- **Runs:** several dozen omp runs. Most were direct delegations, some were probes, and a sizable share came from a separate review workflow's own wrapper script, which duplicates part of the skill.
- **Use cases:** almost all were read-only reviews or second opinions. No run resumed a session, and every delegation used `--no-session`, so omp kept no transcript of any of them.
- **Adherence:** agents followed the launch pattern closely (`--cwd`, explicit `provider/model`, `--max-time`, absolute `@file`, `< /dev/null`). Only a handful of runs used `--mode json`.
- **Duration and cost:** typical runs took 3–10 minutes (range 14 s to 25 min); `xhigh` review lanes took about 8–13 minutes.

Recurring friction, each now addressed in the skill:

| Friction | Fix |
|---|---|
| `omp models --json \| jq '.[].selector'` failed or returned nothing (the output is `{models: [...]}`), in 4 sessions | Exact `jq` path in SKILL.md and troubleshooting |
| A requested model name that did not exist; one silent substitution | No-silent-substitution rule |
| Runs longer than the host's 10-minute command limit; GNU `timeout` missing on macOS | Background-job and TERM guidance |
| A relative `@prompt.md` resolved against `--cwd` ("File not found") | Wrapper uses an absolute path |
| A text-mode run hit its 5-minute deadline with no output; the same prompt in JSON mode finished in about a minute | JSON mode by default (decision 1) |
| The safety classifier blocked 3 launches of the separate review wrapper, each passing `dangerouslyDisableSandbox` | Logged in that workflow's own process log; no Bash sandbox was configured, so the flag looked unnecessary |
| The documented `--no-tools` "length-stop" failure reproduced in a probe | Kept as a historical, scoped diagnosis |

## omp behavior verified on 18.10.3

From source, with the decisive cases confirmed by live runs:

- **Exit status:** exit 1 only for a final `error`/`aborted` stop reason, strict MCP failure, session-store durability failure, or a launch failure such as a missing `@file`. Usage errors exit 2; signals exit 130, 143, or 129. A 1-second deadline exited 0 with no assistant message, and a deadline that interrupts a model turn exits 1. Refused tool calls leave exit 0.
- **Completion:** omp continues after a `stop` that carries tool calls or a `stopDetails.type` of `pause_turn`.
- **Stdin:** print mode reads non-terminal stdin until EOF before starting. After 1 second it prints a "waiting for EOF" notice.
- **Sessions:** an explicit `--session-dir` without `--resume` always creates a new session, even with `autoResume`. `--restore` is interactive-only.
- **Approval:** the default `tools.approvalMode` is `yolo`. With no UI, a tool that needs approval fails with a tool error rather than hanging. `always-ask` allows only read-tier tools, and a tool with no declared tier is treated as exec. MCP tools are write tier; `task` and `eval` are exec tier. Read tier includes web search, URL reads, and `memory_edit`. User `tools.approval` and `bash.patterns` allow rules override the mode.
- **Events:** `message_update` carries deltas only, and `message_end` holds the complete message with `usage` and `stopReason`. `tool_execution_start`/`end` carry the tool name, args, result, and `isError`. Blocking task results include each subagent's `usage`.
- **Effort:** `--thinking` overrides a `provider/model:level` suffix. Without it, effort resolves through the session, selector, role, and model defaults, then the global setting.
- **Records:** `omp stats` walks every folder in the sessions root, groups by top-level folder, and counts nested subagent and advisor transcripts. Print mode never generates session titles.
- **Logs:** per-process files at `~/.omp/logs/omp.<date>.<pid>.log`, all levels by default, filtered with `OMP_LOG_LEVEL`. `PI_DEBUG_STARTUP=1` shows the last startup phase reached.

## Upgrade check: 18.12.3 (2026-10-19)

The [v18.10.4 to v18.12.3 comparison](https://github.com/can1357/oh-my-pi/compare/v18.10.4...v18.12.3) changes several files behind the claims. One claim needed a correction; the rest hold. Paths are under `packages/coding-agent/src/` unless noted, with lines at v18.12.3:

- **Exit status (corrected).** Print mode now waits for the session to settle before it reads the final message (`modes/print-mode.ts:299`). A length-stop that omp's recovery gives up on now exits 1. The recovery stores an error message with `Length-stop recovery gave up …` (`session/session-maintenance.ts:3243-3251`), which `getLastAssistantMessage` returns (`session/agent-session.ts:6566-6567`). In JSON mode the error arrives only as a `notice` event, so the last `message_end` can still show `length`. On 18.10.4 the same run exited 0. [automation.md](../skills/use-omp/references/automation.md#exit-status-and-completion) and [decision 2](decisions.md#2-completion-is-judged-by-the-final-message-not-the-exit-code) now say so. `error`/`aborted` still decide exit 1 (`modes/print-mode.ts:311-316`).
- **Background jobs.** `waitForIdle` waits for streaming, event handlers, and recovery, not for running jobs (`session/agent-session.ts:6497-6515`). Shutdown still cancels the session's own jobs (`session/agent-session.ts:5874-5886`, called from the dispose at `modes/print-mode.ts:368`). The `event-controller.ts` changes cover composer state, session approvals, and idle-compaction timing, not the TUI's wait for jobs.
- **Overlay setting IDs** are unchanged: `async.enabled` (`tools/settings.ts:929`), `bash.autoBackground.enabled` (`exec/settings.ts:111`), `memory.backend` (`memory-backend/settings.ts:13`), and `mnemopi.scoping` with default `per-project` (`mnemopi/settings.ts:36-39`). The `mnemopi` changes do not touch bank scoping. Bash still defaults to a 300-second timeout (`tools/tool-timeouts.ts:11`).
- **Approval.** The default mode is still `yolo` (`tools/settings.ts:314-317`), and `always-ask` still allows only read tier (`tools/approval.ts:150-155`). The new `always-ask-cached` mode and per-session grants are recorded only from interactive answers (`extensibility/extensions/wrapper.ts:365-383`, `452-454`). `--read-only` passes `always-ask`, which never reads those grants. The headless refusal text is unchanged at `extensibility/extensions/wrapper.ts:422-438`. `task` is still exec tier (`task/index.ts:586`). `glob`, `grep`, `ast_grep`, and `find` now compute their tier from the path (`tools/path-utils.ts:1411-1422`): local paths stay read tier, and remote URL schemes can raise it.
- **Events** keep the fields the summarizer reads (`packages/agent/src/types.ts:1267-1293`). `agent_start` gains an optional `resumedToolCallIds`. Task results keep `results[].usage`, `aborted`, and `exitCode` (`packages/tui/src/tools/task.ts`, `SingleResult`), and running jobs still report `details.async.state: "running"` with type `task` (`task/index.ts:1168-1172`) or `bash` (`tools/bash.ts:799`). Text mode now prints Anthropic narration blocks as answer text (`modes/print-mode.ts:332`). JSON mode still emits them as `thinking` blocks with `narration: true`, so `answer.md` ignores them.
- **Subagent models.** A per-call `model` field exists only for the new read-only `seance` agent, which reuses an earlier session's model (`task/seance.ts:175`). Other subagents still resolve through their roles.
- **Unchanged:** `cli/initial-message.ts` (the `@file` block and the typed line, lines 33-41), `cli/file-processor.ts`, and `cli/models-cli.ts`. The `cli/args.ts` change only widens the `approvalMode` type; the `main.ts` changes cover model scoping and startup order.

The live tier passed every behavior probe with `openai-codex/gpt-6-luna:low` on 2026-10-19. The only failure was the version check, before this update.

## How a headless launch differs from the TUI

These differences are now listed in SKILL.md section 2:

1. **Background work is cut off.** Print mode exits when the primary turn ends and cancels background jobs still running (task subagents under `async.enabled`, bash commands over 60 seconds under `bash.autoBackground.enabled`); the TUI waits for them. It also has no todo reminders to keep going.
2. **The task arrives as a file.** It is wrapped as a `<file name="…">` attachment. There is no `ask` tool, and extension prompts get default answers.
3. **`--model` and `--thinking` replace only the run's `default` role.** Subagents use their configured role and fall back to the run's model when the role is unconfigured. In a test, a subagent ran on the `task` role at `medium` while the parent ran at `low`.
4. **Startup counts against `--max-time`.** That includes up to 30 seconds waiting for MCP servers, and a server that isn't ready loses its tools for the run.
5. **`.env` comes from the launch directory**, not from `--cwd`.
6. **Memory is still read and written** when a memory backend is enabled, even with `--no-session`. The bank belongs to the workspace, so earlier runs there, including tests, can surface in a new run.
7. **`--no-session` runs are invisible** to the resume picker, history, `omp stats`, and the Agent Hub. Subagent artifacts go to `$TMPDIR`.
8. **The system prompt is smaller.** Settings-editing guidance and some rendering hints are left out, and settings writes are refused.
9. **The calling agent's environment passes through** to omp's shell commands.

Approval mode, `autoResume`, and the advisor behave the same as interactively for a default configuration. Plan-first (`plan.defaultOnStartup`) does not: print mode ignores it.

## Review findings worth remembering

These were caught in review before shipping:

- An `always-ask` recommendation for reviews that removed the reviewer's ability to prove issues.
- `umask 077` leaking into omp.
- `looks_complete` passing empty or mid-turn messages.
- jq's `^` anchoring only at the start of the string without `(?m)`.
- `files_written` counting refused writes and missing omp's default `hashline` edit format (renamed to `write_targets`).
- `report.sh` crashing on empty or malformed input.
- An async-only overlay that left bash auto-backgrounding on (a separate setting).
- Live probes that read and wrote the user's memory bank, which could let a probe pass from memory.
- A misleading claim that subagents ignore `--model`.
- A worktree recipe that shares branches and stash with the user's repo.

## Usage audit: 2026-10-21

The second audit asked how the skill had been used in the week since the first, from the run ledger (2026-10-14 to 2026-10-21) and the Claude Code sessions that loaded the skill. Scouting used a cheaper model, and each finding below was checked against the raw data or omp 18.12.3's source before it was relied on. It led to decisions 13 to 16 and the revised decision 10.

What usage looked like:

- **Loads:** about a third of sessions started with the slash command and the rest with the model choosing the skill, usually after the user mentioned the skill or omp mid-sentence. Almost every run was a review, a fact check, or a second opinion on a plan or a conclusion.
- **Runs:** all but one looked complete, and over a third resumed an earlier session. Nearly all passed a hand-written memory-off overlay. No run came close to its deadline; a typical run took about four minutes.
- **Models:** two models covered nearly every run, almost always at the same effort. Several sessions ran a provider the user had not asked for, because the agent took the first `omp models` entry for a bare model ID.

| Finding | Change |
|---|---|
| Bare model IDs resolved to whichever provider the catalog lists first; omp's own resolver ranks recent use before `modelProviderOrder` | Wrapper resolves bare IDs by `modelProviderOrder` and refuses to guess (decision 13) |
| Users repeated the same model and effort on most requests | Optional `--model` with `USE_OMP_MODEL` (decision 13) |
| Replies reported list-price cost estimates that were not money spent | Hand-back leaves out cost (decision 14) |
| Callers turned memory off in nearly every run | Memory off by default, `--memory` opts in (decision 10) |
| A third-round `--resume` exited 1 because the first round's worktree had been removed; the summary's `final_error` was empty | One worktree per review across rounds (SKILL.md section 2, troubleshooting); `final_error` takes stderr's last line for a launch failure |
| Run directories neared a gigabyte within a week, mostly progress-only events | Wrapper drops them after exit (decision 4) |
| About half the runs had tool errors, nearly all ordinary failed commands, which buried the real problems in `report.sh` | Tool errors are informational; refusals outside `--read-only` are problems (decision 16) |
| Users wanted second opinions at important junctions, not at every step | Description names checkpoints; consulting unprompted needs the user's opt-in (decision 15) |
